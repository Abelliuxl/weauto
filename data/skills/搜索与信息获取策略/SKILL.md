# 搜索与信息获取策略

## 一、搜索工具选型原则

### Tavily（search_web）
- **适用场景**：通用搜索，中英文均可，返回摘要+结果列表
- **Proxy**：国际内容=true，国内内容=false
- **优势**：有 AI 摘要（Answer 字段），结果结构化
- **劣势**：中文长尾词效果一般
- **query 技巧**：用空格分词，不加标点，不超过 10 个词

### Brave（search_web_brave）
- **适用场景**：英文/国际内容搜索，技术文档、新闻
- **Proxy**：必须 true（国际 API）
- **优势**：结果新鲜度高，对技术类查得准
- **劣势**：国内内容覆盖差
- **query 技巧**：英文关键词优先，可用 site: 限定域名

### Volc Ark Doubao（search_web_volc）
- **适用场景**：国内人物、事件、热点、梗、方言、本地信息
- **Proxy**：不需要（国内 API）
- **优势**：LLM 直接理解 query 并返回自然语言答案，带来源链接
- **劣势**：一次只能搜一个 query，不支持分页
- **query 技巧**：用自然语言问句，越具体越好，如"云南乱哥是谁"而非"乱哥"

### fetch_url
- **适用场景**：已知 URL，抓取静态 HTML 内容（论坛帖子、API 返回、文档页）
- **Proxy**：国内站=false，国际站=true
- **优势**：快，直接拿原始内容
- **局限**：JS 渲染的页面拿不到完整内容
- **注意**：遇到验证码、反爬会返回错误，此时应换 browse_url

### browse_url（Playwright）
- **适用场景**：需要 JS 渲染的页面（SPA、动态加载、看漫画/视频页）、fetch_url 失败后的备选
- **Proxy**：同 fetch_url
- **优势**：完整渲染，能看到 JS 生成的内容
- **劣势**：慢（需启动浏览器 ~2s），不能用于批量抓取
- **注意**：百度搜索等可能会遇到滑块验证码

## 二、失败重试策略

### 搜索无结果时
1. 换搜索工具重试（Tavily → Brave → Volc）
2. 改写 query 再试：换同义词、加限定词、减少词数
3. 先用 search 查到相关 URL，再用 fetch_url/browse_url 抓详情

### fetch_url 失败时
1. 换 browse_url 重试（JS 渲染）
2. 检查 proxy 设置是否正确
3. 尝试拼接不同 URL 变体

### browse_url 失败时
1. 检查是否遇到验证码（返回内容包含"验证"、"滑块"等）
2. 尝试用 search 找到缓存/快照
3. 告知用户无法访问

## 三、Proxy 决策树

```
query/URL 是否是中国大陆服务？
├── 是（国内网站、百度百科、B站、NGA、微博等）
│   └── proxy=false
└── 否（Google、Wikipedia、GitHub、YouTube、Twitter 等）
    └── proxy=true
```

## 四、Query 优化技巧

### 搜索人名
- 全名优先："云南乱哥" 好过 "乱哥"
- 加地域前缀："昆明 乱哥"
- 加身份后缀："乱哥 歌手"、"乱哥 主播"

### 搜索事件/新闻
- 加时间限定："2026年 云南 乱哥"
- 加来源限定：site:weibo.com、site:douyin.com
- 用事件关键词而非模糊描述

### 搜索技术问题
- 英文优先（技术资料英文覆盖面广）
- 用错误信息的关键部分
- 加版本号

## 五、信息整合流程

1. 优先用 search_web/search_web_brave/search_web_volc 做初步搜索
2. 从搜索结果中找到有价值的 URL
3. 用 fetch_url 或 browse_url 抓取详细内容
4. 综合多个来源的信息，去重、交叉验证
5. 用自然语言组织回复
